# T-001.5 — Write `api.md`

## Description
Backend documents the Application Programming Interface surface for `[insert backend framework here]`: protocol (REST, GraphQL, or remote-procedure call), naming and error conventions, authentication and authorization model, rate-limit policy, versioning and deprecation rules, and where the machine-readable schema lives (OpenAPI, GraphQL Schema Definition Language, or protobuf). This is a **Tier 1, contract-critical** doc and the narrative companion to `contracts.md`: the exhaustive route list lives in `contracts.md`; `api.md` documents the **conventions and the procedure for adding or changing a route safely**. Held to the Grounding & Completeness Protocol (`AGENTS.md` § 6.0).

## Acceptance criteria
- [ ] `/docs/api.md` exists.
- [ ] Documents protocol, base URL pattern, error envelope — grounded in the real router/handler code, with paths cited. If greenfield, marked **forward-looking**.
- [ ] Documents authentication and authorization (headers, scopes, token lifetime).
- [ ] Documents rate-limit and abuse-prevention policy.
- [ ] Documents versioning and deprecation window, and the **backward-compatibility / deprecation procedure** an agent must follow when changing or removing an existing route.
- [ ] Explicitly cross-references `contracts.md` as the exhaustive endpoint inventory and states that the two must be updated together.
- [ ] Links to the machine-readable schema (OpenAPI, GraphQL Schema Definition Language, or protobuf) and states whether it is generated and how to regenerate it.
- [ ] Any fact not confirmable from code or the human is written `UNKNOWN — needs human confirmation`, never guessed.
- [ ] Includes an "update-this-doc-when" footer naming the route/handler paths that require this doc to be updated.
- [ ] All 9 agents have signed off.
