# T-008 — Make every user-facing error name a next step, and say what actually failed

## Description
Found while drafting the Tier 1 docs (T-001). These are recorded facts, not changes made by T-001 (plan rule 9). Each item cites its source. The docs that record it are listed in `docs/contracts.md`, `docs/architecture.md` § 7, `docs/data-model.md`, `docs/testing.md` and `docs/deployment.md`, in their follow-ups sections.

## Items
- [ ] Messages that name no next step: `httpError` `422` and the fallback; `askError` `413`, `422` and the fallback; `speakError` `503` and the fallback; the preview timeout; "No key moments found."; "Couldn't find the YouTube player". See `docs/contracts.md`, User-facing message contracts.
- [ ] `httpError` replaces every `504` with "Summarizing timed out", even for key moments and transcription (`background.js:579`).
- [ ] Backticks show literally everywhere except `showError`, including the no-token and `502` messages.
- [ ] The "Piper not installed" message names a CLI flag but appears in the browser as a 503 (`audio.py:199`).
- [ ] A missing `claude` binary shows up as "internal error" on streamed calls (`claude_client.py:333`). This is inferred from the code, not run.
- [ ] The panel and worker timeouts are equal for ask (300 s) and key moments (320 s), so which message the user sees depends on timing.
- [ ] With `whisper: "always"`, the panel's 160 s summarize timer fires before the worker's 40-minute budget (`background.js:144-145`, `content.js:670`), so the panel says to check `tldw serve` while the work goes on.
- [ ] The panel's voice preview has no ping and no safety timer (`content.js:1421-1438`).
- [ ] The busy message "Already reading 2 summaries aloud" is also sent for `/preview`, where it doesn't describe what the user did (`server.py:645-647`).
- [ ] The Options custom-backend note names `tldw config llm_cmd`, which exits 1 (`options.js:60-63`; the fix is tracked in T-012).

## Acceptance criteria
- [ ] Each item above is fixed with a guarding test, or recorded as an accepted decision (an ADR when it crosses a redline), or answered by the owner.
- [ ] Every doc that records an item is updated in the same PR, under the `/docs` gate.
