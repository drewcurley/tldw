# T-001.4 — Write `data-model.md`

## Description
Data Engineer documents the schema for `[insert database here]`: **every** table/collection, indexes, foreign keys, personally identifiable information classification, and the migration approach (tooling, reversibility expectations, deploy sequencing). This is a **Tier 1, contract-critical** doc: a future agent must be able to change the schema without breaking a dependent query, migration, or consumer using only this file + `contracts.md`. Held to the Grounding & Completeness Protocol (`AGENTS.md` § 6.0) — exhaustive and code-grounded, not a sample.

## Acceptance criteria
- [ ] `/docs/data-model.md` exists.
- [ ] Lists **every** table/collection (not a sample) with columns, types, indexes, and foreign keys — grounded in the actual schema/migrations, with the source path cited. If greenfield, marked **forward-looking**. For column-level detail on a large schema, this doc **may point to a reproducible schema dump / migrations directory** rather than hand-copying — reserve hand-authored prose for what a dump can't capture (PII classification, consumers/blast radius, migration sequencing). The pointer must be exact and reproducible.
- [ ] Every table/column entry is reconciled against the real schema (migrations dir / ORM models / live schema dump). The verification method is recorded in the doc.
- [ ] Marks every personally identifiable information / regulated column and its protection (encryption-at-rest, masking, access control).
- [ ] Documents migration tooling, naming convention, reversibility rules, deploy sequencing, and backfill expectations — i.e. **how to change the schema safely**.
- [ ] For each table, notes the known consumers / blast radius (which services, queries, or contracts depend on it) so a future change can reason about what it might break.
- [ ] Documents partitioning, sharding, or replication approach if applicable.
- [ ] Any fact not confirmable from code or the human is written `UNKNOWN — needs human confirmation`, never guessed.
- [ ] Includes an "update-this-doc-when" footer naming the schema/migration paths that require this doc to be updated.
- [ ] All 9 agents have signed off.
