# T-001 — Bootstrap /docs/ folder

## Description
Per `AGENTS.md` § 0, no feature work happens until the **Tier 1** `/docs/` content is populated. Tier 2 content must be populated by the end of the first feature sprint. Both tiers run through the Docs Bootstrap Workflow (`AGENTS.md` § 6): every agent drafts the doc(s) in their domain, the Review Coordinator runs the 3-round review on the assembled draft, and only when all 9 agents sign off does any file in `/docs/*` land on `main`.

**The standard:** the goal is not "docs that describe the project" but a living memory complete and accurate enough that a future agent who has read only `/docs/` can commit with high confidence it will not break an existing route, data contract, integration, or behavior. Every doc is held to the **Grounding & Completeness Protocol** (`AGENTS.md` § 6.0) — grounded in real code, no invented facts, exhaustive where it's a contract. The contract-critical docs (`contracts.md`, `api.md`, `data-model.md`) are in Tier 1 so that inventory exists before the first feature commit.

Tier 1 = the minimum context **plus the full contract inventory** every engineer needs before writing the first line of feature code. Tier 2 = the deeper reference material that catches up during the first sprint of feature work.

### What tldw is (every drafter starts from the same facts)
- **Size:** about 9,800 lines.
  - `src/youtube_tldw/`: 22 Python modules plus `__init__`. The largest are `server.py` (1,971 lines), `claude_client.py`, `cli.py` and `summarize.py`.
  - `extension/`: MV3, plain JS: `content.js` (1,937), `background.js` (581), `options.js`, `options.html`, and two manifests.
  - `tests/`: 660 tests.
- **No database, no cloud, no hosting.**
- **Data** is JSON and other files on disk, `chrome.storage.local`, the Claude CLI's own session files, and the JSON and NDJSON that the extension and the loopback server exchange.
- **Secrets:** tldw's token is `~/.config/youtube-tldw/token` (0600) or `TLDW_TOKEN`. tldw never reads a keychain. Do **not** copy T-003's older "keychain" line.
- **What leaves the machine:**
  - transcripts and questions go to Anthropic through the `claude` CLI, on the user's plan;
  - YouTube is reached through yt-dlp and a direct caption fetch;
  - model files are downloaded for Piper and faster-whisper.
- **No regulated domain applies.** YouTube's terms for yt-dlp downloads are written `UNKNOWN — needs human confirmation`.

### Rules for every doc (Grounding & Completeness Protocol § 6.0, plus this repo's)

3. **Exhaustive** wherever something is a contract.
4. **Each contract entry** states its invariant and its blast radius.
5. **"How this was verified"** for each doc.
6. **An "update this doc when" footer.**
7. **N/A, with a reason, for every T-001.17 category that doesn't apply:**
   - feature flags (there are none: say so, and point to the env vars that behave like flags);
   - events and webhooks: the NDJSON stream events count as the event schema, and there are no webhooks;
   - a machine-readable schema: none, the inventory *is* the schema;
   - tables, indexes, foreign keys, partitioning: N/A, file-backed.
   
   "Background jobs" must list every `threading.Thread` or `Timer` start, and the sweeps.
8. **Public repo: no real data.** Docs and artifacts must never contain:

### Mechanical checks
**Committed as `tests/test_docs_contracts.py`** (Test Engineer, who wins on coverage), so `contracts.md` can't drift after this merges. It is modelled on `tests/test_isolation.py::test_conftest_covers_every_home_path`. It runs in CI through `ci-tldw-tests.sh`, with no new shell suite.
- One parametrized test per category, so a failure names the category and the missing item.
- Matching is on exact backticked tokens.
- `EXCLUDED = {item: reason}` lives in the test, and every entry needs a reason. Shadow-root selectors are excluded this way, with the reason recorded.
- **A count floor for each extractor,** so an extractor that breaks and finds zero fails.
- **Reverse checks for routes, env vars and storage keys:** anything listed in the doc but gone from the code fails. The storage-key extractor reads shorthand properties too (`options.js:137`, `{ serverUrl, token, … }`).
- **One negative test:** a known route is removed from a copy of the doc, and the failure names it.
- **The deterministic leak check** runs over `docs/` and the new task files. It looks for:
  - `/Users/`, `/home/`, `C:\Users`, `-Users-`;
  - the secret patterns from `ci-checks.sh`;
  - placeholder text.
