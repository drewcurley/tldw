# T-001 — Bootstrap /docs/ folder

## Description
Per `AGENTS.md` § 0, no feature work happens until the **Tier 1** `/docs/` content is populated. Tier 2 content must be populated by the end of the first feature sprint. Both tiers run through the Docs Bootstrap Workflow (`AGENTS.md` § 6): every agent drafts the doc(s) in their domain, the Review Coordinator runs the 3-round review on the assembled draft, and only when all 9 agents sign off does any file in `/docs/*` land on `main`.

**The standard:** the goal is not "docs that describe the project" but a living memory complete and accurate enough that a future agent who has read only `/docs/` can commit with high confidence it will not break an existing route, data contract, integration, or behavior. Every doc is held to the **Grounding & Completeness Protocol** (`AGENTS.md` § 6.0) — grounded in real code, no invented facts, exhaustive where it's a contract. The contract-critical docs (`contracts.md`, `api.md`, `data-model.md`) are in Tier 1 so that inventory exists before the first feature commit.

Tier 1 = the minimum context **plus the full contract inventory** every engineer needs before writing the first line of feature code. Tier 2 = the deeper reference material that catches up during the first sprint of feature work.

## Risks / dependencies
- Tier 1 requires every agent to have access to enough project context to draft their section accurately. If unsure, ask the human user — do not invent facts.
- Tier 1 blocks feature work; communicate the timeline to stakeholders.
- Tier 2 is a commitment, not a suggestion. If Tier 2 slips past the first sprint, that is a process failure and should be retrospected.
