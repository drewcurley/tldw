# T-013 — Fix server and CLI edge-case bugs the bootstrap found

## Description
Found while drafting the Tier 1 docs (T-001). These are recorded facts, not changes made by T-001 (plan rule 9). Each item cites its source. The docs that record it are listed in `docs/contracts.md`, `docs/architecture.md` § 7, `docs/data-model.md`, `docs/testing.md` and `docs/deployment.md`, in their follow-ups sections.

## Items
- [ ] `--host ::1` passes the loopback check, then fails to bind, because the server is IPv4-only (`server.py:1935`, `:1941`).
- [ ] A busy port gives a raw `OSError` traceback, not a message (`server.py:1941`).
- [ ] A JSON body that isn't an object sent to `/speak` or `/speak/stream` closes the connection with no response (`server.py:1465`).
- [ ] An empty body is answered `413 "request body too large"` (`server.py:1142`).
- [ ] A stop during transcription arrives as a 500, not a 499.
- [ ] Buffered `/summarize` always reports the transcript source as `captions` and ignores `page`.
- [ ] `tldw config set` skips validation when the key is spelled with underscores (`cli.py:318-330`).
- [ ] `/ask/stream`'s body cap is set in two places (`server.py:780`, `:1015`).
- [ ] A `TLDW_LLM_CMD` whose first word is `claude` is treated as the stock CLI, so streaming calls drop its arguments.

## Acceptance criteria
- [ ] Each item above is fixed with a guarding test, or recorded as an accepted decision (an ADR when it crosses a redline), or answered by the owner.
- [ ] Every doc that records an item is updated in the same PR, under the `/docs` gate.
