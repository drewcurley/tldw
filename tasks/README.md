# Tasks — One File Per Task

> Durable record of every task on this project. **One file per task** so parallel engineers don't collide on a single ledger.

## Layout

```
tasks/
├── README.md       # this file
├── INDEX.md        # derived at-a-glance table; regenerated by the Review Coordinator
├── _TEMPLATE.md    # copy this when opening a new task
└── T-NNN.md        # one file per task or subtask
```

## Conventions

- **Stable IDs.** `T-001`, `T-002`, … Subtasks use dotted IDs (`T-001.1`, `T-001.2`) and each lives in its own file.
- **Frontmatter is source of truth.** The YAML at the top of each file is what `INDEX.md` is derived from. The body is human context.
- **Append-only activity log.** Inside each task file. Never rewrite history — add a new line.
- **Never delete a task file.** If cancelled or superseded, set `state: cancelled` and explain in the **Notes** section. The trail is the point.
- **One task file per pull request (when possible).** Touch the task file you're working on; don't bulk-rewrite others. That keeps merge conflicts off the ledger.

## States

`proposed → in-review → in-progress → completed | blocked | cancelled`

| State | Meaning |
|-------|---------|
| `proposed` | Captured but not planned yet. Analyst hasn't drafted acceptance criteria. |
| `in-review` | Plan exists; running through the review cycle for plan sign-off. |
| `in-progress` | Plan signed off; build happening on a branch. |
| `completed` | Merged to `main`, all sign-offs collected, tests green. |
| `blocked` | Stuck on an external dependency or unresolved decision. Explain in Notes. |
| `cancelled` | Decided not to do. Explain why in Notes. |

## When you start work

1. Pick or create a task file. New tasks: copy `_TEMPLATE.md`, pick the next free ID.
2. Set `state: in-review`, fill in `created`/`updated`, and append a line to the activity log.
3. Run the plan-review cycle (`AGENTS.md` § 2).

## When you commit

- Update `state`, `branch`, `commit` (short SHA), `review_artifact` (path) in the frontmatter.
- Append a line to the activity log.
- Commit the task-file update **in the same pull request** as the underlying work.

## INDEX.md

- Generated, not hand-edited.
- Review Coordinator regenerates it at the end of every review cycle from the frontmatter of each `T-NNN.md`.
- Don't bother resolving merge conflicts on `INDEX.md` — regenerate instead.
