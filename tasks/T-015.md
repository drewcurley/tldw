# T-015 — Get human answers for the docs' UNKNOWNs

## Description
Found while drafting the Tier 1 docs (T-001). These are recorded facts, not changes made by T-001 (plan rule 9). Each item cites its source. The docs that record it are listed in `docs/contracts.md`, `docs/architecture.md` § 7, `docs/data-model.md`, `docs/testing.md` and `docs/deployment.md`, in their follow-ups sections.

## Items
- [ ] Does a custom `serverUrl` (another port, or `localhost`) work from the extension, given `host_permissions` of `http://127.0.0.1:8765/*`? Needs a browser test.
- [ ] Firefox's origin: does the Firefox build work without `--allow-origin`? A `moz-extension://` origin gets no CORS header by default (measured).
- [ ] Extension rollback: needs a throwaway browser profile.
- [ ] The pipx rollback (`pipx install --force .`), the recommended install, is untested: the tested rollback used a plain venv to stay isolated (`docs/deployment.md` § 10). Test it with `PIPX_HOME` and `PIPX_BIN_DIR` pointed at temp dirs.
- [ ] Whether the `claude` CLI finds its login under a separate `HOME`.
- [ ] The effect of the ruleset's `require_extra_approval_for_unattributed_changes: true` when 0 approvals are required.
- [ ] YouTube's terms of service for yt-dlp downloads.
- [ ] Licensing: piper-tts is GPL-3.0-or-later, and tldw has no license. The licenses of the `claude` CLI, the voice models, the Whisper weights and the other dependencies are also unknown.
- [ ] The Claude CLI's session format, file modes and retention; whether it writes into `CLAUDE_DIR`; faster-whisper's on-disk layout; Piper's download host.
- [ ] For the hackathon: can people without push access open fork PRs into `hackathon/demo`; where should questions and security reports go (there is no `SECURITY.md`); who else has write access.
- [ ] Whether `docs/agents/` (the agent briefs mirrored in `/docs`, per `AGENTS.md:96`) is wanted, and where reduced-scope reviews keep their artifacts.
- [ ] Whether there is a deprecation window for server routes, and how long it is (`docs/api.md` § 8, UNKNOWN). Also whether buffered `/summarize` and `/speak` have callers outside this repo.
- [ ] Alternatives that were never recorded as weighed: the extension framework or bundler, the server framework (Flask, FastAPI, aiohttp), file storage vs SQLite, native messaging, alternatives to yt-dlp, the TTS choice, and Pillow (`docs/stack.md:34`, `:42`, `:45`, `:48`, `:57`, `:78`, `:81`, `:87`; ADR 0001 options 3–5 (option 3: calling the Anthropic API directly); ADR 0003 option 3). An answer from the owner, or confirmation that none were weighed.
- [ ] Facts that depend on each user's setup: where Anthropic processes data, and whether a data-residency commitment is wanted (`docs/architecture.md:124`); where a custom `TLDW_LLM_CMD` backend sends the payload (`docs/architecture.md:209`); whether a credential can end up in `llm_cmd`, and if so how `config.json` should be classed (`docs/data-model.md:336`). The owner answers each, or rules it out of scope with an N/A and a reason.
- [ ] Whether an unprivileged local process can read loopback traffic, on each supported platform (ADR 0003, "what voids it").
- [ ] Whether Chrome and Firefox apply CORS to the extension's own fetches, given `host_permissions` (`docs/api.md` § "Known weaknesses"; `docs/contracts.md`, the `do_OPTIONS` row).

## Acceptance criteria
- [ ] Each item above is fixed with a guarding test, or recorded as an accepted decision (an ADR when it crosses a redline), or answered by the owner.
- [ ] Every doc that records an item is updated in the same PR, under the `/docs` gate.
