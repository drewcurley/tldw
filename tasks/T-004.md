# T-004 — Reduce token exposure (startup print, ps, file modes, child env, extension storage)

## Description
Found while drafting the Tier 1 docs (T-001). These are recorded facts, not changes made by T-001 (plan rule 9). Each item cites its source. The docs that record it are listed in `docs/contracts.md`, `docs/architecture.md` § 7, `docs/data-model.md`, `docs/testing.md` and `docs/deployment.md`, in their follow-ups sections.

## Items
- [ ] `tldw serve` prints the token on every start (`server.py:1959`): a screen-share and log-paste leak.
- [ ] `--token` is visible to other local users in `ps` (`cli.py:306`).
- [ ] Owner-only modes are applied after the file exists: the token (`server.py:706-707`), `usage.jsonl` (`usage.py:187-189`) and `CLAUDE_DIR` (`claude_client.py:148-149`). Create them owner-only from the start.
- [ ] Child processes inherit the full environment, including `TLDW_TOKEN` when it is set (`claude_client.py:135`, `proc.py:82-90`).
- [ ] The extension keeps the token in plain text in `chrome.storage.local` (`options.js:137-138`). The storage area isn't restricted to trusted contexts (no `setAccessLevel`), and content.js's `onChanged` listener is handed the new token whenever Options saves one (`content.js:50-55`).
- [ ] The token is sent to whatever `serverUrl` holds (`background.js:108-110`, `options.js:97`).

## Acceptance criteria
- [ ] Each item above is fixed with a guarding test, or recorded as an accepted decision (an ADR when it crosses a redline), or answered by the owner.
- [ ] Every doc that records an item is updated in the same PR, under the `/docs` gate.
