# T-005 — Harden the server and integration trust boundaries (Origin, Host, timeouts, URL checks, redirects)

## Description
Found while drafting the Tier 1 docs (T-001). These are recorded facts, not changes made by T-001 (plan rule 9). Each item cites its source. The docs that record it are listed in `docs/contracts.md`, `docs/architecture.md` § 7, `docs/data-model.md`, `docs/testing.md` and `docs/deployment.md`, in their follow-ups sections.

## Items
- [ ] The Origin check only gates CORS headers, not requests, and any installed Chrome extension's origin passes by default (`server.py:917-939`, `:924`).
- [ ] No `Host` header check, so DNS rebinding can read the open GETs `/health` and `/voices`.
- [ ] No socket timeout, and `ThreadingHTTPServer` starts one thread per connection with no limit, so a slow unauthenticated client can hold threads (`server.py:1924-1925`).
- [ ] `videoIdFromUrl` accepts any hostname ending in `youtube.com`, and `content.js` is injected before that check runs (`background.js:31`).
- [ ] The caption fetch checks its host allowlist on the first URL only; `urlopen` follows redirects unchecked (`metadata.py:157-182`).
- [ ] yt-dlp metadata and subtitle calls follow the user's own yt-dlp config; only the audio download passes `--ignore-config`.
- [ ] Unknown POST paths answer 404 before the token check, so the routes can be mapped without a token (`server.py:1017-1019`).

## Acceptance criteria
- [ ] Each item above is fixed with a guarding test, or recorded as an accepted decision (an ADR when it crosses a redline), or answered by the owner.
- [ ] Every doc that records an item is updated in the same PR, under the `/docs` gate.
